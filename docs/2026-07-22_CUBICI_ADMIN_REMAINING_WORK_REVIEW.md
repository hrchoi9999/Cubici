# Cubici Admin Remaining Work Review

## 작업 결과

- 관리자 페이지 추가 개발 필요 내역을 중요도별로 정리했다.
- 현재 관리자 화면은 사용자용 페이지 개발로 넘어갈 수 있는 수준인지 판단했다.

## 현재 기준

- Legacy 최종 Depth 메뉴 기준: 21개 중 21개가 실구현 또는 부분구현 상태
- React 실구현 화면: 29개
- 보수적 관리자 진행률: 약 63~67%
- 전체 프로젝트 진행률: 약 31% 내외

## 사용자용 페이지 전환 전 반드시 확인할 핵심 항목

| 구분 | 내역 | 판단 |
|---|---|---|
| 신청/심사/계약 | 신청 접수, 심사 승인, 계약 관리의 상태 변경 흐름 재검증 | 중요 |
| 정산/상환 | 정산/상환 금액 산식, 취소/재계산, 잔액 불일치 가능성 검산 | 중요 |
| 펌뱅킹 | mock 송금요청/응답/결과조회 저장 흐름과 실제 반영 정책 분리 | 중요 |
| 서류/메모 | 관리자 심사메모, 서류 확인값 저장 E2E 재확인 | 중요 |
| 권한/보안 | 관리자 등록/승인/삭제와 실제 접근권한 연동 정책 | 중요 |

## 사용자용 페이지 개발과 병행 또는 후순위 가능 항목

| 구분 | 내역 | 판단 |
|---|---|---|
| Legacy chart | 통합정보/머니뱅크 chart 산식 1:1 검산 | 후순위 가능 |
| 환경설정 CRUD | 요금제/프로모션/협력사/머니뱅크 상품의 live DB CRUD 세부 검증 | 병행 가능 |
| 고객관리 | 문의/공지/FAQ 첨부파일, 문자/이메일 실제 발송 연동 | 후순위 가능 |
| 모니터링 | OS metric, 운영 로그 원천 데이터 연결 | 후순위 가능 |
| Prism System | RawData 계산식, Excel download, legacy 정규화 테이블 검산 | 병행 가능 |
| 디자인 미세조정 | font size, padding, table column width 등 legacy와의 픽셀 단위 차이 | 후순위 가능 |

## 관리자 화면별 남은 작업 요약

| 화면 | 현재 상태 | 남은 작업 | 우선순위 |
|---|---|---|---|
| 신청 접수 | DB/API/서류/메모/E2E 구현 | 상태 전환 정책 최종 검증 | 높음 |
| 심사 승인 | DB/API/화면 구현 | 승인/반려 후 계약/상환 연계 검증 | 높음 |
| 계약 관리 | DB/API/화면 구현 | 계약 상태, 수수료, 서류 흐름 재검증 | 높음 |
| 정산 관리 | DB/API/화면 구현 | legacy 정산 산식 검산 | 높음 |
| 상환 관리 | 작업/취소/E2E 구현 | 취소 발생 시 재계산 정책 검산 | 높음 |
| 펌뱅킹 전문 | mock 요청/응답/결과조회 flow 구현 | 실제 반영 정책과 대사 화면 설계 | 높음 |
| 회원관리 | 목록/상세/결제/상태 구현 | 결제이력 원천, 평가메모 write 보강 | 중간 |
| 환경설정 | 대부분 CRUD 구현 | live DB CRUD, 권한/삭제 정책 확인 | 중간 |
| 고객관리 | 문의/문자/공지 구현 | 첨부파일/실제 발송 연동 | 낮음 |
| 모니터링 | Error/Server/펌뱅킹 구현 | 운영 로그/OS metric 연동 | 낮음 |
| Prism System | 지표/RawData 구현 | legacy 계산식/Excel download 검산 | 중간 |

## 판단

- 관리자 페이지는 핵심 업무 흐름을 대부분 볼 수 있고, mock 펌뱅킹 흐름까지 구현되어 사용자용 페이지 개발로 넘어갈 수 있다.
- 단, 정산/상환/펌뱅킹 결과 반영은 금융 운영 리스크가 있으므로 사용자용 페이지 개발과 병행해 별도 검산 backlog로 유지해야 한다.
- 디자인 미세조정과 legacy chart 1:1 복원은 현재 단계에서 blocker가 아니다.

## 다음 액션

1. 사용자용 페이지 개발로 전환한다.
2. 관리자 잔여 핵심 항목은 `정산/상환 산식 검산`, `펌뱅킹 결과 반영 정책`, `승인/계약 상태 전환 검증` 3개 backlog로 관리한다.

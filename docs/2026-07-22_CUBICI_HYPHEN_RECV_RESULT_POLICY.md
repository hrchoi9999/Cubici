# Cubici Hyphen RECV_MSG Result Policy

## 작업 결과

- legacy `TRADE_REQUEST_BIN.RECV_MSG` 결과코드 분포를 확인했다.
- 하이픈 300 byte 전문 기준의 성공/실패/재조회 정책을 1차 정리했다.
- 관리자 화면 브라우저 검증 중 필요한 로컬 CORS 설정을 추가했다.

## 성공 판정 원칙

문서 기준:

- 공통부 `은행응답코드`가 `0000`
- 개별부 `처리결과`가 있으면 해당 값도 `0000`
- 위 조건을 모두 만족할 때만 정상 처리로 본다.

업무별 판정:

| 전문 | 정상 조건 | 정책 |
|---|---|---|
| 송금이체 응답 `0110100` | 은행응답코드 `0000` | 송금 요청 정상 접수/처리 후보 |
| 처리결과조회 응답 `0610101` | 은행응답코드 `0000` + 원거래 처리결과 `0000` | 원거래 최종 성공 |
| 잔액조회 응답 `0610300` | 은행응답코드 `0000` | 잔액 반영 가능 |
| 계좌조회 응답 `0610400` | 은행응답코드 `0000` | 예금주/계좌 확인 성공 |
| 입금통지 `0200300` | 수신 전문 검증 성공 + 중복 아님 | 상환/입금 후보 처리 |

## 실패/보류 판정 원칙

| 조건 | 판정 | 후처리 |
|---|---|---|
| `RECV_FLAG = T` | timeout | 처리결과조회 전문으로 재조회 |
| `RECV_FLAG = C` | 접속실패 | 재전송 또는 관리자 확인 |
| `RECV_FLAG = F` | 응답수신실패 | 재조회/관리자 확인 |
| 은행응답코드 blank/null | 미완료/불명 | 재조회 |
| 은행응답코드 `0000` 아님 | 요청 실패 또는 은행 오류 | 금액 반영 금지, 코드별 관리자 확인 |
| 처리결과조회에서 원거래 처리결과 `0000` 아님 | 원거래 실패/반려/불명 | 금액 반영 금지, 기존 반영분 있으면 대사 대상 |

## Cubici 반영 정책

1. 송금/지급 금액 반영은 `0610101` 처리결과조회로 최종 성공이 확인된 뒤 수행한다.
2. `0110100` 송금응답의 은행응답코드가 `0000`이어도 최종 성공으로 단정하지 않는다.
3. timeout, 접속실패, 응답수신실패는 자동 금액 반영을 금지하고 재조회 대상으로 둔다.
4. 동일 `COMP_CODE + BANK_CODE + REQ_DATE + SEQ_NO`는 idempotency key로 취급한다.
5. 같은 원거래 전문번호에 대해 성공/실패 결과가 혼재하면 관리자 대사 대상으로 분류한다.
6. 상환/정산 잔액 반영 후 취소나 실패 결과가 발견되면 대사 backlog에 남긴다.

## 로컬 CORS 설정

관리자 화면 검증을 위해 FastAPI에 로컬 origin CORS를 추가했다.

기본 허용 origin:

- `http://127.0.0.1:5174`
- `http://127.0.0.1:4175`
- `http://127.0.0.1:4173`

환경변수:

- `CUBICI_CORS_ALLOW_ORIGINS`

운영 배포 단계에서는 Cloudflare/운영 도메인 기준으로 별도 제한해야 한다.
